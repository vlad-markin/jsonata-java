## Фаза 1. Совместимость по официальному test-suite

**Точка порта.** Исходники портированы с jsonata-js ~2.0.3 (середина 2023) и подтянуты до 2.0.5.
Дальше изменения переносились выборочно («Backport: …»). Сабмодуль `jsonata` указывал на
`98f23c5` (v2.2.2 + 2 коммита), но он определяет только test-suite, а не перенос исходников.
В ветке оценки сабмодуль переключён на тег **v2.2.2**. Подробности:
[phase1/upstream-delta.md](phase1/upstream-delta.md).

**Генерация через `com.dashjoin.jsonata.Generate`** из test-suite v2.2.2: 102 группы, 1686 случаев.
`mvn test`: 1792 теста, 0 падений, 3 пропущено. **Это обманчивые 100%**: `JsonataTest` не сравнивает
коды ошибок (засчитывает любое исключение, включая NPE), применяет `timelimit/depth` только при
наличии `bindings` и пропускает 33 случая по overrides.

**Строгий прогон** (`suite/run-suite.sh`, через diff-runner): значение (порядок ключей не важен,
как в chai), код ошибки, `token`/`position`, если они заданы в тесте; overrides не применяются.

| | случаев |
|---|---:|
| всего | 1686 |
| прошло строго | **1589 (94,2%)** |
| упало | 96 (+1 только по token) |
| из них покрыто overrides | 29 |
| не покрыто overrides (прежний харнесс их не видел) | 68: 55 — Java-исключение вместо ошибки JSONata, 11 — другой код ошибки, 2 — другое значение |
| jsonata-js 2.2.2 на том же наборе | 1686/1686 |

Таблица по группам и все упавшие случаи: [suite/RESULTS-2.2.2.md](suite/RESULTS-2.2.2.md).
Основные группы падений: `function-formatNumber` (20), `function-fromMillis` (18),
`function-tomillis` (9), `function-number` (7), `transform` (5, T0410), `tail-recursion` (3:
`setRuntimeBounds` бросает ошибку без кода U1001).

**Overrides** ([phase1/overrides-review.md](phase1/overrides-review.md)): ни одна из 30 записей не
обоснована принципиальной разницей Java/JS. Одна устарела, одна частично связана с разницей
regex-движков, остальные скрывают ошибки порта. Две из них дают молчаливо неверный результат:
`$parseInteger(...,'w')` переполняет `long`, а `alternateResult` для `[w]` в `$fromMillis`
закрепляет неверное значение.

**Не перенесено из JS (v2.0.0..v2.2.2):** 32 коммита: перенесено 14, не перенесено 4, частично 3,
только для JS 11. Главное:
- **df63a7c**: без `bindings` все вызовы `evaluate` делят одно окружение. Переменные, `$$` и
  счётчики guardrails утекают между вызовами и потоками. Пример: `$y := ($exists($y) ? $y+1 : 1)`
  дважды: JS `1, 1`, Java `1, 2`. При параллельном вызове результаты неверные.
- **91532d4**: `$append` не учитывает лимит `sequence`.
- **2dd49c6, d6ffc17**: разбор дат через фиксированные regex и `java.time`; нет D3110,
  исключения без кода.
- **0a7aa35** (частично): guardrails падают с NPE, если задан `timeout`/`stack`, но не `sequence`.
- Java **опережает** 2.2.2 в двух местах: `$split`/`$replace` с undefined-шаблоном
  (в 2.2.2 ошибка без кода) и лимит `$pad` 1e7. Для требования «как 2.2.2» это тоже расхождения,
  но в пользу JVM.
