# Инструменты миграции выражений (фаза 4)

## Детектор и переписыватель

`compat.migration.Migrate` (Java, без зависимостей, в модуле `compat-eval/jvm`). На вход —
JSONL `{"id", "expr", "ast"}`, где `ast` — дерево в формате `ast()` jsonata-js. Его может построить
любой совместимый парсер, в том числе ваш на Kotlin. Текст выражения нужен, чтобы найти токены
и переписать их: в AST jsonata-js есть только позиция *конца* токена, а значение regex
сериализуется в JSON как `{}`.

```bash
node migration/ast.js corpus.jsonl > corpus-ast.jsonl          # AST от jsonata-js 2.2.2
java -cp jvm/target/classes compat.migration.Migrate [--rewrite] [--all] [--warnings] corpus-ast.jsonl findings.jsonl
```

Выход — по строке на находку:
`{"id","rule","severity","position","message","recommendation","fixedInFork","fix":{"start","end","text"}?}`.
С `--rewrite` для каждого переписанного выражения добавляется строка
`{"id","type":"rewrite","expr","rewritten","rules"}`.

- `rule` — id из [../divergences.md](../divergences.md);
- `position` — позиция токена по правилам jsonata-js (индекс после токена);
- `fix` — замена `[start, end)`. Её дают только правила с безопасной заменой и только если
  токен однозначно найден в тексте. Иначе выдаётся только сообщение;
- `--all` включает правила для расхождений, уже исправленных в этом форке. Они нужны для другого
  JVM-движка (исходный dashjoin, будущий движок на Kotlin) и как регрессионная сетка;
- `--warnings` отбрасывает находки уровня info.

## Правила

| правило | что находит | серьёзность | переписывание |
|---|---|---|---|
| DT-05 | `$fromMillis(…, …, '-HHMM')` / `$now(…, '-HHMM')` с минутами ≠ 00 | warning | **да**: `'-HHMM'` → `'-(HH+1)MM'` (так JS 2.2.2 фактически применяет пояс) |
| ORD-01 | конструктор объекта с литеральными ключами вида целого числа в порядке, отличном от JS; группировка `{}` с вычисляемыми ключами | warning / info | нет: в AST нет начала значений пар, поэтому переставить пары нельзя (только сообщение) |
| STR-03 | `$base64encode`/`$base64decode` не с ASCII-литералом | warning | нет (нужно решение, см. вопросы) |
| NUM-10 | `x / 0`, `x % 0` с литеральным нулём | warning | нет |
| NUM-11 | `$power`, `$sqrt` | info | нет |
| RE-07 | regex-литерал с символами вне BMP (эмодзи) | warning | нет |
| UND-03 | regex с необязательными группами (`|`, `)?`, `)*`) | info | нет |
| PAD-01 | `$pad` с шириной > 1e7 (в JVM D2016, перенесено из JS после 2.2.2) | warning | нет |
| API-01* | присваивание на верхнем уровне | info | нет |
| NUM-01* | `=`/`!=` с конструктором массива или объекта | warning | нет |
| SORT-02* | `$sort` с компаратором `>=`/`<=` | warning | нет |
| UND-01* | литеральный `null` аргументом функции | warning | нет |
| DT-03* | шаблон с `[X]`, `[w]`, `[x]` | warning | нет |
| RE-01* | regex с JS-специфичным синтаксисом (`[^]`, `\0`, тождественные escape, `\s`, `$`) | warning | нет |

\* — исправлено в форке, выводится только с `--all`.

## Проверка правил переписывания (п. 4.3)

`node migration/verify.js cases.jsonl out/dir`: строит AST, переписывает выражения и прогоняет
diff-runner, где jsonata-js вычисляет исходное `expr`, а JVM — переписанное (`exprJvm`).
Результат для DT-05: **352 из 352** переписанных выражений эквивалентны (7 шаблонов × 11 поясов ×
6 моментов времени, `$now`, вход из данных); `migration/verify-dt05-summary.json` (копия `out/verify-dt05/verify-summary.json`).

Прогон детектора по test-suite 2.2.2 и 8000 выражениям фаззинга (9686 выражений) занимает 1,9 с.
