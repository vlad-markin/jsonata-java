# Фаза 5: нагрузочный стенд jsonata-js 2.2.2 vs JVM-движок

Стенд сравнивает время и память вычисления одних и тех же выражений на одних и тех же данных
в jsonata-js 2.2.2 (Node) и в этом форке (JVM). Выводы и результаты: [../phase5/performance.md](../phase5/performance.md),
управление вычислением: [../phase5/control.md](../phase5/control.md).

## Состав

| файл | что делает |
|---|---|
| `gen.js` | детерминированный генератор модели «architecture as code» (mulberry32, seed 42): `systems → containers → components → {tags, properties, relations}`, глубина 5; 1 система = 5 контейнеров × 20 компонентов |
| `queries.json` | 14 выражений: пути с фильтрами, группировки `{}` с агрегатами, join (линейный поиск в лямбде и через индекс `$merge`/`$lookup`), `$sort`/`^()`, `$map/$filter/$reduce`, строки, regex, рекурсия по дереву, хвостовая рекурсия, fib |
| `js/bench.js` | раннер для Node (`--expose-gc`) |
| `jvm/` | maven-модуль: `compat.bench.Bench` (раннер JVM), `compat.bench.ControlProbes` (пробы управления вычислением). Движок компилируется из `../../../src/main/java` (рабочее дерево) без `module-info.java` |
| `compare.js` | сравнение результатов JS и JVM (JSON, порядок ключей не важен) |
| `report.js` | сводные таблицы markdown + `results.csv`, `modes.csv` |
| `run-bench.sh` | полный прогон: генерация, JS, JVM, сравнение, режимы накладных расходов, сводка |
| `prof.sh`, `jfr_agg.py` | профилирование JFR и агрегация (top self/inclusive frames, типы и места аллокаций) |
| `run-probes.sh` | пробы управления вычислением (отмена, тайм-ауты, виртуальные потоки, потокобезопасность) |

## Воспроизведение

```bash
cd compat-eval && npm ci            # jsonata@2.2.2 (зафиксирован в package-lock.json)
cd bench
./run-bench.sh                      # ~25-35 мин на 4 ядрах; результаты в ../phase5/results/
SIZES="10000" SKIP_MODES=1 ./run-bench.sh /tmp/quick   # быстрый прогон
./prof.sh                           # JFR-профили в ../phase5/results/profile/
./run-probes.sh                     # пробы в ../phase5/results/control-probes.txt
```

Требуется: Node 22, JDK 21, Maven. Сгенерированные данные (`data/`, 3.5/18/71 МБ) в git не
хранятся и воспроизводятся побайтно.

## Методика (кратко)

* Один процесс на размер и движок; все запросы подряд в одном процессе. Данные читаются один раз
  (время разбора JSON не входит в измерение). Компиляция выражения измеряется отдельно (медиана 200).
* Прогрев: `W` итераций (10/5/3 для 10k/50k/200k), но не дольше 15 с; затем до `I` итераций
  (30/15/10), не меньше 3 и не дольше 20 с суммарного измеряемого времени на запрос.
* Перед каждой итерацией принудительная сборка мусора (`global.gc()` / `System.gc()`), вне замера.
* JVM: `-Xms4g -Xmx4g -XX:+UseG1GC`, один поток. Аллокации на вычисление считаются точно через
  `com.sun.management.ThreadMXBean.getCurrentThreadAllocatedBytes`; пик кучи — сумма пиков heap-пулов
  за запрос (включая ~данные).
* Node: `heapUsed` после минус до (нижняя оценка аллокаций, если во время вычисления был GC; число
  GC фиксируется через `PerformanceObserver`), `maxRSS` процесса (монотонный).
* Результат первой итерации каждого запроса сохраняется и сравнивается между движками.
* JMH не используется; это осознанный компромисс (см. «Угрозы достоверности» в performance.md).
